## Key decisions / findings

- **Cluster-side branch checkout initially failed twice, for two unrelated
  reasons** — worth recording so the next cluster deploy doesn't hit the
  same two traps blind:
  1. `git checkout frontend-visualization` failed with "pathspec did not
     match" even though the branch existed on GitHub (confirmed via
     `git ls-remote --heads origin` from this machine before troubleshooting
     — the push had gone through cleanly). Cause: `git pull` only updates
     the branch you're already on; it doesn't fetch refs for brand-new
     remote branches. Fix: `git fetch origin` first, then checkout — git
     auto-creates the local tracking branch once the ref exists locally.
  2. After fetching, checkout failed again: the cluster's working tree had
     local, uncommitted changes to `models/pipeline_evaluation.json` (from
     an earlier, pre-bootstrap-fix job run there) and an untracked
     `models/discordance_sensitivity.json` that collided with what's
     tracked on `frontend-visualization`. Fixed with
     `git stash --include-untracked` (bundles everything in one shot,
     reversible, nothing deleted) before retrying the checkout — worked
     cleanly, and git auto-set up the tracking branch on checkout.
  3. Confirmed cluster HEAD matches local HEAD exactly before submitting
     anything (`1a29660 fix(bootstrap): vectorize resampling; add
     selection-bias and planned_return cross-checks`) — did not submit the
     job blind.
