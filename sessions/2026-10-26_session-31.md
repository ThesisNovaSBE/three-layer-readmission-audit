  timestamps for a coherent chronological chain (`features.csv` Sep 4 →

  `stage3_batch_results.csv` Oct 6 → `pipeline_evaluation.json`/
  `discordance_subgroup_evaluation.json` Oct 7) and cross-checked every

  `stage3_batch_results.csv` reported 10,048 lines, not the documented

  quoted `clinical_justification` text, not a real duplicate/stale-data
  problem — confirmed via `pandas` (9,899 rows, 9,899 unique `hadm_id`, 0
  duplicates, single consistent `model_name`).
- **Selection-bias table built** (`scripts/analyze_selection_bias.py`,
  new) — didn't exist anywhere before (flagged gap, `ARCHITECTURE.md` §4).
  Used `has_discharge_note` (already computed in `features.csv` against
  the real MIMIC-IV-Note file — the authoritative flag, not inferred
  indirectly). Real result: notes-covered vs. excluded is 60.2%/39.8% of
  Stage 1's test partition; the notes-covered group is clinically
  distinct (older 59.7 vs 52.1, sicker — Charlson 2.24 vs 1.43, far more
  often an emergency admission — SMD=0.73, the largest gap by a wide
  margin) but has a **nearly balanced outcome rate** (19.8% vs. 17.8%,
  SMD=0.053, below the 0.1 imbalance flag). Real caveat for the thesis
  text: RQ1/RQ2 are evaluated on a population skewed toward older,
  sicker, emergency-admitted patients — but that skew isn't an
  outcome-rate confound.
- **Performance bug found and fixed in `src/model/bootstrap.py`** — not
  something I went looking for; it blocked the next item. Re-running
  `evaluate_pipeline.py` (needed to add CIs to two more pipeline arms)
  ran 39+ minutes without finishing. Root cause: `bootstrap_ci`'s
  resampling loop called `np.where(group_of == g)` once per *sampled
  patient*, *per resample* — O(n_unique_patients × n_rows) work repeated
  1,000 times. Fixed by precomputing each patient's row positions once
  via `pandas`' Cython groupby (`pd.Series(groups).groupby(groups).indices`)
  before the resample loop, then doing O(1) dict lookups inside it.
  **Verified bit-for-bit identical output** against the old algorithm on
  a small case with the same seed, then benchmarked the realistic scale
  (n=100k, ~70k unique patients, 1000 resamples): **24 seconds**, vs. a
  real run that hadn't finished after 39 minutes. This was already a
  known, named open item in `ARCHITECTURE.md` §4 ("bootstrap.py's
  resampling performance") — now closed, and it speeds up *every*
  existing bootstrap CI in the codebase, not just the two new ones.
- **Bootstrap CIs added for `notes_cohort` and `conditional_triggering`**
  (`src/model/evaluate_pipeline.py`) — the infra already existed and was
  already wired into `full_cohort`/`control_arm_stage1_matched`; this was
  two missing `groups=` pass-throughs (`_pipeline_report`'s call sites)
  plus a new `groups` parameter on `_conditional_triggering_report`.
  Reran the full evaluation (58 seconds total, post-fix) and confirmed:
  **every existing number (`full_cohort`, `control_arm`) is byte-identical
  to the pre-fix run** — this was a pure speed + coverage fix, zero
  change to any already-reported result. New CIs:
  `notes_cohort` precision=0.433 [0.416, 0.450], recall=0.180 [0.168,
  0.193]; `conditional_triggering` precision=0.437 [0.420, 0.457],
  recall=0.319 [0.301, 0.339].
- **`planned_return` cross-check built** (`scripts/
  analyze_planned_return_crosscheck.py`, new) — never examined anywhere
  before (flagged gap, `ARCHITECTURE.md` §6). Compared Stage 3's
  note-derived `planned_return` against the structured,
  `admission_type`-based "unplanned" proxy, restricted to Stage-3-audited
  patients who were actually readmitted within 30 days (n=4,375) — the
  only population where "was the readmission planned" has a structured
  answer at all. **Real, non-trivial finding, not just a formality**:
  raw agreement is 81.7% — which sounds fine in isolation, but a trivial
  "always predict unplanned" baseline already scores 95.8% (the
  structured-planned rate is only 4.2%), so **Stage 3's actual agreement
  is below the trivial baseline**. Stage 3 calls "planned" 4.5× more
  often than the structured proxy does (19.2% vs. 4.2%) — of Stage 3's
  842 "yes" calls, only 112 (13.3%) match the structured proxy. This
  reads as the LLM being substantially more liberal about reading a note
  as describing a planned return than the structured data would license
  — worth flagging explicitly in the thesis as an open discrepancy
  between the two signals, not quietly reporting the 81.7% number alone.
