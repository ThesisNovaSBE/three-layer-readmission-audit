## Key decisions / findings

- **The discordant-cases story from session 27 was incomplete, and the
  corrected picture is less flattering to Stage 3, not more.** Built
  `scripts/analyze_discordance_subgroups.py` (runs entirely locally --
  `stage2_results.csv` already has the true label + `subject_id` for this
  cohort, `stage3_batch_results.csv` already has `discordance_mode` and
  `decision_model` stored from the real run; a hadm_id join is all that's
  needed, no cluster round-trip). It isolates exactly the comparison
  session 27's framing was missing: Stage 3's real decision vs. "Stage 1's
  flag stands," **within each discordance subgroup separately**:

  | Subgroup | Policy | Precision | Recall | F2 |
  |---|---|---|---|---|
  | Concordant (n=4,662) | Stage 1 alone | 0.447 | 1.000 | 0.801 |
  | | Stage 3 | 0.443 | 0.771 | **0.671** |
  | Discordant (n=5,131) | Stage 1 alone | 0.409 | 1.000 | 0.776 |
  | | Stage 3 | 0.423 | 0.682 | **0.608** |

  By F2 (the metric this project uses throughout, appropriate since
  missing a true readmission is costlier than a false alarm), Stage 3
  makes things *worse* in **both** subgroups relative to trusting Stage
  1's flag -- and the drop is actually **larger on discordant cases**
  (-0.168) than concordant (-0.130), because recall falls further there
  (32 points vs 23 points) and F2 weights recall heavily. Stage 3 does buy
  a small, real precision gain on discordant cases (+1.4pp) that it
  doesn't buy on concordant cases (flat/slightly negative) -- but that
  gain doesn't come close to compensating for the recall given up, in
  either subgroup.

  This doesn't overturn session 27's finding (removing Stage 3 from the
  concordant group is still a clean win -- it has zero redeeming precision
  value there), but it does overturn the implication that Stage 3 "adds
  value on discordant cases." The honest statement: Stage 3's overrides
  trade recall for little-to-no precision gain almost everywhere they're
  applied; the trade is unambiguously bad on concordant cases and still a
  bad trade (just a smaller precision win, more than offset by a bigger
  recall loss) on discordant cases. This matters for the thesis -- the
  conditional-triggering framing alone would have overstated the auditor's
  value; this is the more complete and more defensible story.
- **Real data-governance catch**: building the per-admission export the
  user asked for (`models/stage3_full_evaluation_export.json` -- true
  label + all Stage 1/2/3 fields merged, for further ad hoc investigation)
  created a file containing verbatim quotes from real MIMIC-IV-Note text,
  the same sensitivity class as `stage3_batch_results.csv` -- but as a
  `.json` file, it fell outside the existing `.gitignore`'s `*.csv` rule
  and was one `git add -A` away from being committed. MIMIC-IV-Note is
  PhysioNet-credentialed data under a DUA that prohibits redistributing
  the data (or derived products containing substantial excerpts) outside
  the credentialed environment, even to a private repo, unless every
  collaborator with access is independently credentialed -- a real
  compliance constraint, not a style preference. Added an explicit
  `.gitignore` rule for this specific file. Aggregate-only result files
  (`pipeline_evaluation.json`, `discordance_sensitivity.json`,
  `discordance_subgroup_evaluation.json` -- counts/metrics only, no
  patient-level text) remain trackable, consistent with what the project
  already committed before this session.

## Next steps for whoever continues (model-evaluation roadmap)

Roughly in priority order:

1. **Qualitative read-through of the false negatives.** Pull the specific
   admissions where Stage 3 overrode a genuine 30-day readmission (both
   subgroups combined, ~1,144 cases) from `stage3_full_evaluation_export.json`
   and read a sample the same way the 50-patient validation runs were read
   -- is there a recurring, fixable reasoning pattern (a specific ground
   being over-trusted, a systematic misreading of "stable at discharge"),
   or are these defensible clinical judgment calls that are simply wrong
   in hindsight (30-day readmission has real stochastic components no
   auditor, human or LLM, could reliably predict)? This is the single most
   likely source of a genuinely new, interesting thesis finding left on
   the table right now.
