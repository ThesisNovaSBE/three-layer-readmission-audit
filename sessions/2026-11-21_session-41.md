## Key decisions made

- **Leakage guard (new `scripts/check_results_no_identifiers.py`):** scans a
  JSON for hadm/subject keys, 8-digit ints in the MIMIC id range, MIMIC de-id
  markers (`___`, `[**`), and free-text keys. The four new JSONs are clean; it
  correctly flags the 30 `sample_hadm_ids` in the committed
  `results/stage3_validation_controls_summary.json`.
- **Docs updated to the 2026-11-21 rerun** (MODEL_CARD.md + results/README.md),
  old numbers moved to a labelled block in "Changes between the old run and the
  rerun". Headline RQ2 softened: the rerun's control arm is only nominally ahead
  (P 0.444 vs 0.439, R 0.328 vs 0.324) with overlapping 95% CIs -- the old run's
  clear recall gap is gone. Subgroup F2 drops shrank (concordant -0.056,
  discordant -0.070 vs old -0.130/-0.168). `planned_return` agreement 93.4%
  (still below the 95.8% majority baseline) with LLM/structured rates now
  matched at 4.2% (old 19.2% vs 4.2%). With user approval, also overwrote the
  stale `results/*.json` copies with the new values (leakage-checked).
- **`scripts/compare_pipeline_control_paired.py` (CPU only):** patient-level
  PAIRED bootstrap of pipeline-minus-control differences in precision and
  recall (1,000 resamples, seed 42, same patient-cluster scheme as
  `compare_stages._paired_auroc_diff_ci`), for the primary, secondary
  (both-override), and conditional (discordant-only, vs a control matched to
  ITS volume) policies. Reconstructs per-admission predictions by importing
  `evaluate_pipeline` helpers unchanged; control arms built with the same
  top-m-by-raw-Stage1-score rule; runtime cross-check asserts each
  reconstructed arm matches `pipeline_evaluation.json` before reporting.
  Writes `models/pipeline_paired_differences.json` (aggregates only).
- **`scripts/summarize_stage3_run.py` (CPU only):** from
  `stage3_batch_results.csv` + `.raw.jsonl`, writes
  `models/stage3_run_summary.json` -- decision counts, model/rule agreement
  among decided, quote-verified share, truncation, planned_return dist,
  invalid/insufficient/prep-failure counts, raw-answer key-order check against
  `_generation_schema()`, and optional `--logs` CUDA-OOM retry count. Emits
  counts only; the OOM-retry log lines contain hadm_ids so only the count is
  kept.
- **Item 4:** added a MODEL_CARD data-handling note that
  `stage3_validation_controls_summary.json` must be committed without
  `sample_hadm_ids`, and flagged (no history rewrite) that the committed
  `results/` copy currently holds 30.
