### FusionLongformer dropped

Flagged that fusion (structured features + note, jointly trained) was
probably not worth pursuing. Checked and agreed: `models/` has never
contained fusion weights — every evaluated Stage 2 number that exists
(`stage2_evaluation.json`, 2026-08-01) is from the plain, note-only
Longformer. Worse, `src/stage2/train.py` had been fully rewritten around
fusion (session 13) with no way left in the code to reproduce the working,
already-evaluated plain model. Reverted `src/stage2/{train,dataset,predict,
_utils}.py` to their pre-fusion versions (git commit `8a4af36` — verified via
`git log` that this is the last commit before fusion was introduced, and that
its public API — `train_stage2`, `predict_stage2`, dataset functions — is
identical to what callers use today, so this was a clean revert, not a
rewrite). Deleted `src/stage2/model.py` (the `FusionLongformer` class).

Reasoning for the decision, not just the mechanics: note-only is the cleaner
independence story for Layer 3's discordance measure (Stage 1 ~40 structured
features, Stage 2 zero — unambiguous, no caveat needed), it was never
trained so dropping it costs nothing already built, and training it for the
first time would cost a full GPU run for a design whose only role was one
row of the secondary comparison study, not the thesis's actual contribution.

`docs/ARCHITECTURE.md`, `README.md`, `PROJECT_TLDR.md`, `MODEL_CARD.md`).
The Stage 3 prompt template itself said "This model saw the same structured

### Implemented every "pure code, no GPU needed" item from the audit

**Isotonic calibration for Stage 1** (remediation review task 0.1). New
`src/model/calibration.py`: `fit_isotonic_calibrator` (fit on OOF predictions
— already held-out relative to the model that produced them, so no new
leakage surface), `apply_calibration` (backward-compatible pass-through for
artifacts without a stored calibrator), `calibration_report` (Brier
before/after). Wired into `train.py` (fit + store in artifact + save
`models/stage1_calibration.json` with a reliability-curve breakpoint
representation), and applied everywhere a Stage 1 score is produced:
`evaluate.py`, `evaluate_pipeline.py`, `stage2/predict.py`, `api.py`. Isotonic
regression is monotonic, so this does not change which admissions get
flagged under capacity or recall-floor policies — only what the reported
probability means (Brier, any threshold reported as a probability, and the
input to Stage 3's percentile-rank discordance calc, which was already
rank-invariant but is now reasoning over a better-calibrated score too).

**Bootstrap CIs** (remediation review task 0.6). New `src/model/bootstrap.py`:
generic `bootstrap_ci(y_true, y_score, metric_fn, groups=...)` with
patient-level (`subject_id`) cluster resampling — a patient with multiple
admissions gets all of them resampled together, not independently. Wired
into `evaluate.py` for AUROC/AUPRC/precision/recall at the primary operating
point. Not yet wired into `evaluate_pipeline.py`'s full/notes-cohort numbers
— noted as still open rather than silently claimed done.

**`readmission_30d_unplanned` label variant** (P7b). `admissions` table's
outcome (next) admission type is now captured via the same `shift(-1)`
pattern already used for `next_admittime`; the label excludes returns whose
own `admission_type` is `ELECTIVE` or `SURGICAL SAME DAY ADMISSION`. A
structured-data proxy, not a note-derived one (the remediation review's
original proposal used an LLM-extracted `planned_return` flag, which needs
evidence-extraction infrastructure that doesn't exist). Added the matching
column to the synthetic-data generator too (set equal to the all-cause
label there — synthetic data has no richer signal to derive it from, and
this is only used for code-correctness checks, not results). New column
flows through `build_features`'s `keep` list and is excluded from
`feature_columns()` the same way `TARGET_COL` already is. Not yet wired into
any training/evaluation script — exists in the feature matrix, unused so far.

## Key decisions made

- FusionLongformer is not part of this thesis's modeling plan. If joint
  fusion is wanted later, it needs to be built again — the code is gone, not
  paused.
- Isotonic calibration applies everywhere a Stage 1 score reaches a
  downstream consumer, not just in the evaluation report — consistency
  matters more here than minimizing the diff.
- `readmission_30d_unplanned` ships as an available column, not a forced
  default — deciding when/whether to report results under it is a writing
  decision for later, not something to force into `split_xy`'s signature now.
- Deleted (git rm) rather than kept-with-a-banner for
  `stage3_discordance_analysis.json`, unlike the docs/*.md superseded files —
  because its content isn't historically informative (it's a bug
  demonstration, not a decision record) and it's cheaply regenerable once
  the batch runner exists, whereas the docs record reasoning worth keeping.
