### Phase 3 — Debugging (2026-07-29 to 2026-07-30)

Two jobs (15067448, 15098411) failed within 26 seconds, both reporting ExitCode 0 incorrectly. Root causes found and fixed:

**Bug 1 — `os.environ["CUDA_VISIBLE_DEVICES"] = ""`**
Location: `setup_stage2.py` line 46 (pre-fix).
This was a macOS workaround to prevent MPS from conflicting with joblib. On Linux/cluster it disabled the GPU entirely, silently forcing CPU training.
Fix: wrapped in `if sys.platform == "darwin":` so it only fires on Mac.

**Bug 2 — Dict subscript access on Pydantic AppConfig**
Location: `setup_stage2.py`, `check_prerequisites()` and `main()`.
Multiple occurrences of `cfg["stage1"]["model"]`, `cfg["data"].get(...)`, `cfg["run"]["mode"]`, `cfg['stage2']['model_name']`, etc. Pydantic v2 models are not subscriptable — these all raise `TypeError: 'AppConfig' object is not subscriptable`.
Fix: converted all to dot access (`cfg.stage1.model`, `cfg.run.mode`, etc.).

**Bug 3 — No `set -e` in bash job script**
`train_stage2.sh` had no `set -e`. When Python exited with code 1, bash continued to `echo "Finished"` and exited with code 0. Slurm reported ExitCode 0, hiding the crash entirely.
Fix: added `set -e` and `set -o pipefail` to the job script header.

**Bug 4 — Stage 1 artifact missing on cluster**
`models/` was excluded from the initial rsync. The script hit `sys.exit(1)` immediately on artifact check — masked by Bug 3.
Fix: rsync `models/stage1_xgboost.joblib` separately to the cluster.

**Bug 5 — Missing `set -e` masking all errors**
See Bug 3. Combined with Bug 4, this caused two 26-second "successful" failures that each wasted a ~16-hour wait in the job queue.

## Key decisions made

- **KISSKI over local GPU**: KISSKI A100 80GB has 8× the VRAM of the RTX 3080, allowing larger batch size and no gradient checkpointing. Training time per epoch is comparable despite 2.5× more data.
- **249k notes**: Use ~99% of available training data (vs. 40% at 100k). Cell caps set high enough that they hit natural limits; 70+ group still oversampled.
- **bf16**: A100 supports bf16 natively — more numerically stable than fp16 and no loss scaling needed.
- **Crash recovery**: Step-level checkpointing every 500 steps (~12 min intervals) retained from previous session. If job hits 48h wall-time limit, resubmit without changes — auto-resumes from latest checkpoint.

## Stage 3 redesign (2026-07-31)

Carried out in this session while Stage 2 training was queued/running.

**Problem with old Stage 3:** narrated Stage 1 XGBoost features via phi4-mini — essentially SHAP explanation + LLM, a well-trodden pattern with no novel finding. Stage 2 was completely invisible to it.

**New design — Cross-Modal Discordance Analysis:**

Stage 3 now processes ALL Stage 1 flagged patients (confirmed AND rejected by Stage 2).  For each patient it feeds phi4-mini:
- Top-k SHAP features from Stage 1 (structured risk drivers)
- Top-n sentences from the discharge note with highest Clinical-Longformer attention weight (Stage 2's internal signal, extracted via `output_attentions=True`)
- Stage 2 decision + confidence

phi4-mini returns JSON: `discordance_mode` + `primary_category` + `explanation`.

Population-level aggregation of these annotations across the full test set produces the thesis research finding: **which clinical domains in discharge notes systematically explain the predictive gap between structured EHR data and free-text clinical notes**.
