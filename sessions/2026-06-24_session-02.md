### 2. Researched readmission prediction on MIMIC-IV structured data

Before writing any code, we researched how published work approaches 30-day readmission prediction on MIMIC-IV with tabular/structured data. Key findings:

- Readmission is a **rare, imbalanced event** — typically only ~2–6% of admissions result in a 30-day readmission in real data. This drives every modelling decision.
- **Performance ceilings are modest** — the literature reports AUROC around 0.65–0.72 and low AUPRC (~0.10–0.20) from structured data alone. We should not expect to beat this; closing that gap is exactly the motivation for Stage 2 (clinical notes).
- **Gradient-boosted trees** (XGBoost, LightGBM, HistGBT) are the consensus best on tabular EHR data.
- **Standard imbalance handling:** XGBoost `scale_pos_weight = neg/pos` + `eval_metric="aucpr"`; `class_weight="balanced"` for sklearn models; decision-threshold tuning after training for the high-recall mandate.
- **Leakage prevention is critical:** must split by patient ID (`subject_id`), never by admission, because one patient can have many admissions.

All research and the resulting plan were written to `docs/MODELING_PLAN.md`, which includes literature-backed Optuna search ranges, expected wall-clock times, and the full pipeline design.

### 3. Implemented the full Stage 1 pipeline

This was the bulk of the session. We built a complete structured-data readmission prediction pipeline — all the way from synthetic data generation through feature engineering, hyperparameter tuning, model training, and evaluation. Here is what each piece does:

**Data layer (`src/data/`):**

- `comorbidity.py` — Implements the Charlson Comorbidity Index using the Quan et al. (2005) ICD-9/ICD-10 code mapping with original Charlson (1987) weights. This is the strongest structured signal for readmission prediction. The code takes a patient's diagnosis codes, matches them against ~17 comorbidity categories by prefix, applies hierarchy rules (e.g. metastatic cancer cancels the milder "malignancy" category), and returns a weighted index score. Self-contained, no external dependencies — "build it ourselves" per the professor's principle.

- `synthetic.py` — Completely rewritten. Instead of producing a flat feature table, it now generates **raw MIMIC-IV-like tables** (patients, admissions, long-format measurements, diagnoses_icd) so that the feature engineering code can run identically on synthetic and real data. The readmission label comes from a latent logistic risk model with signal in age, comorbidity burden, prior admissions, emergency admission, length of stay, discharge destination, and a couple of lab values. This makes the synthetic data actually **learnable** (the model can find real patterns) at a realistic-ish ~10–27% base rate.

- `features.py` — The single feature-engineering path for both real MIMIC-IV and synthetic data. It loads raw tables (auto-detecting real vs. synthetic), applies cohort filters (age ≥ 18, exclude deaths, exclude elective), and builds a rich feature matrix: demographics (age, gender), index-admission traits (length of stay, emergency flag, came-via-ED, discharged-to-facility, admit hour/weekend/night), prior utilisation (count of prior admissions, prior ED visits, days since last discharge), Charlson comorbidity index + number of comorbidities, lab values (last + mean/min/max per admission for 8 labs), and last vital signs (6 vitals). Also computes subgroup columns (gender, age band) carried through for fairness analysis but never used as model inputs.

**Model layer (`src/model/`):**

- `splits.py` — Patient-level grouped stratified splitting. Every split groups by `subject_id` so no patient's admissions ever appear in both train and test. Uses scikit-learn's `StratifiedGroupKFold`.

- `models.py` — Factory that builds the three Stage 1 algorithms:
  - **Logistic Regression:** L2 penalty, `class_weight="balanced"`, wrapped in a Pipeline with median imputation and standard scaling (both fitted per-fold, preventing leakage).
  - **XGBoost:** `hist` tree method (CPU, fast on Apple Silicon), `eval_metric="aucpr"`, `scale_pos_weight = neg/pos`, n_estimators via early stopping (capped at 2000, stops after 50 rounds without improvement). No GPU needed.
  - **HistGradientBoosting:** scikit-learn's built-in GBT, `class_weight="balanced"`, native NaN handling, built-in early stopping. Very fast, no extra dependencies.
  Also contains Optuna search spaces for each model (ranges from `docs/MODELING_PLAN.md`).

- `metrics.py` — All evaluation logic: AUPRC (primary metric), AUROC (secondary), Brier score (calibration), threshold selection (highest threshold still achieving recall ≥ target), operating-point report (recall/precision/specificity/F2/confusion matrix), recall trade-off table at multiple targets (0.80/0.85/0.90), and per-subgroup AUROC for fairness (gender, age band).

- `cv.py` — Shared cross-validation logic. For XGBoost, carves a small inner grouped validation set out of each fold's training data for early stopping, so early stopping never peeks at the fold's scoring data.

- `tune.py` — Optuna hyperparameter search. Maximises mean CV AUPRC over grouped stratified folds. Uses `MedianPruner` to stop unpromising trials early. Writes best params to `models/<model>_best_params.json`.

- `train.py` — Loads tuned params (if available, else defaults), computes out-of-fold predictions on the training set for threshold selection (no test set leakage), fits the final model on the full training set, and saves everything (model + threshold + split indices + metadata) to `models/stage1_<model>.joblib`.

- `evaluate.py` — Loads the saved model artifact, scores the held-out test set (touched only here, never during tuning/training), and produces the full evaluation report: AUPRC, AUROC, Brier, operating point, recall trade-off, subgroup AUROC. Prints it and saves to `models/<model>_metrics.json`.

### 4. First successful end-to-end run (quick mode, synthetic data)

Martin ran the full pipeline on his MacBook (M5) and it completed successfully in under a minute total:

```
python setup_demo.py              # generated synthetic data + feature matrix
python -m src.model.tune          # 15 Optuna trials, ~30 seconds
python -m src.model.train         # trained final XGBoost, ~10 seconds
python -m src.model.evaluate      # scored held-out test set
```

**This was a quick-mode run on ~4,000 rows of synthetic (fake) data. The results are only a code-correctness check, NOT scientific findings.** The synthetic data has a deliberately higher readmission rate (~27%) and embedded signal to make it learnable for testing purposes.

Results on synthetic data (quick mode, XGBoost):
- AUPRC = 0.609 (vs ~0.27 base rate — model learned signal), AUROC = 0.798
- At the 0.85 recall target: recall=0.855, precision=0.430 — catches 86% of readmissions but with many false alarms (which is the whole point — Stage 2 prunes these)
- Subgroup AUROC roughly equal across genders (~0.80 each); lower for youngest (18–40: 0.68) and oldest (70+: 0.70) age bands, best for 41–70 (~0.85)
- Brier = 0.162 (reasonable calibration)

On real MIMIC-IV data with `--mode full`, we expect substantially lower numbers (AUROC ~0.65–0.72, AUPRC ~0.10–0.20) — this is well-documented in the literature and is the motivation for adding Stage 2.

## Key decisions made

- **3 models** selectable via `config.yaml stage1.model`: `logistic_regression`, `xgboost`, `histgradientboosting`.
- **Charlson Comorbidity Index** implemented now (not deferred) using Quan 2005 ICD-9/10 mapping with original Charlson weights.
- **Synthetic generator** produces raw MIMIC-like tables (not flat features) so `features.py` is a single code path for both real and synthetic data.
- **Imbalance handling:** cost-weighting (`scale_pos_weight` / `class_weight="balanced"`) + post-training threshold tuning. SMOTE is an optional config flag but not the active path.
- **Leakage prevention:** patient-level (`subject_id`) grouped + stratified split everywhere. Imputation/scaling for LR done inside a per-fold Pipeline. XGBoost early stopping uses an inner grouped validation set carved from each fold's training data.
- **Primary metric:** AUPRC. Secondary: AUROC. Also report Brier, operating point (recall/precision/specificity/F2 + confusion matrix), recall trade-off at 0.80/0.85/0.90, and per-subgroup AUROC (gender, age band) for fairness.
- **Threshold rule:** pick the highest probability threshold whose recall is still ≥ the target. This maximises precision at the recall floor. Stage 2 recovers further precision from the flagged set.
- **Quick vs full mode** controlled via `config.yaml run.mode` or `--mode` CLI flag. Fixed random seeds throughout for reproducibility.
- **sessions/ is append-only** — never edit or overwrite a prior session entry.
