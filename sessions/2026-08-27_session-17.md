### Population-wide Layer 2 scoring (RQ1 prerequisite)

`src/stage2/predict.py` only ever scored Stage 1's flagged subset —
correct for the cascade, but it meant Layer 2 could never be fairly
compared against Layer 1 on the same population. Refactored the shared
scoring logic (`_prepare_population`, `_score_core`) so `predict_stage2`
(cascade, unchanged behavior) and a new `predict_stage2_all` (population-
wide) share one pipeline instead of duplicating it. `predict_stage2_all`
writes `models/stage2_results_all.csv`. Added `--all` and `--limit` CLI
flags (the latter for smoke-testing locally without a full cluster run).

**Bug found while actually running the smoke test, not just unit-testing
it:** `python -m src.stage2.predict` (standalone CLI, with or without
`--all`) segfaults on macOS ARM — exit 139, crashes before printing
anything. Proved this is pre-existing, not introduced today, by running the
same command against the unmodified pre-session-17 code (`git stash`) —
same crash. Root cause: the MPS/XGBoost C-extension conflict already
documented elsewhere in this codebase (`api.py`, `setup_stage2.py`) —
`joblib.load()`-ing the XGBoost artifact after torch has initialised
crashes on Apple Silicon, and `src.stage2.dataset` transitively imports
torch, so no amount of reordering within `predict.py` alone fixes it (tried
the standard `PYTORCH_ENABLE_MPS_FALLBACK` env-var mitigation first — it
does not fully fix this case). Confirmed the actually-safe path instead:
called `predict_stage2_all` with a pre-loaded artifact, matching
`setup_stage2.py`'s own working pattern (load the artifact via `joblib`
before anything imports torch) — verified end-to-end via an ad hoc script,
successfully scored 12 real notes against the existing stale models,
produced a correctly-shaped `stage2_results_all.csv` (deleted after, it's
from stale pre-retrain models, not a result). Documented both the bug and
the safe workaround inline in `predict.py` and in `docs/ARCHITECTURE.md`;
a full fix (lazy torch imports throughout) is out of scope for this session.

### N1 comparison runner — the RQ1 answer

New `src/model/compare_layers.py`. Joins Stage 1's test-partition scores
with the new population-wide Layer 2 scores on `hadm_id` (Layer 2 only
covers admissions with a note), reports both models' AUROC/AUPRC with
patient-level bootstrap 95% CIs, an operating point for Layer 2 matched to
Layer 1's alert volume within that cohort (Layer 2 has no canonical
standalone threshold outside the cascade), and a *paired* bootstrap CI on
the AUROC difference (same resampled admissions score both models each
draw — narrower and correct here, unlike two independent CIs subtracted).
Explicitly flags the notes-cohort-vs-full-population denominator question
as unresolved in its own output rather than picking one silently.

### Batch Stage 3 runner — the RQ2 prerequisite

New `src/stage3/batch.py`. `explain_patient` (existing) is on-demand,
single-patient, built for the API. `run_batch_audit` runs it over every
admission in `stage2_results.csv`, preloading the artifact/results/feature
matrix once instead of per-call, writing results incrementally (flushed
per row) so an interrupted or flaky Ollama run doesn't lose completed work,
and isolating per-admission failures so one bad note doesn't kill the
batch. Supports `--limit` (smoke test) and `--resume` (skip hadm_ids
already written).

### Discordance-threshold sensitivity sweep

Realized the sweep doesn't need to recompute percentile ranks — only the
mode *classification* depends on the pp threshold, `displacement` values
don't. `sweep_discordance_thresholds` (pure function, `src/stage3/explain.py`)
reclassifies an existing `displacement` column across a range of thresholds;
`run_sensitivity_sweep` / `--sweep` in `batch.py` wires it to
`stage3_batch_results.csv`. Makes the provisional `discordance_displacement_pp
= 20` actually checkable once real batch results exist, without new LLM calls.

### Layer 3's model call generalized

`call_phi4mini` → `call_llm(prompt, cfg, model_name=None)` in
`src/stage3/explain.py`; `explain_patient` gained a matching `model_name`
passthrough. Added `stage3.robustness_model` to config, deliberately left
`null` — this is a real decision (see below), not a default to assume.

### Pipeline's final prediction now prefers Layer 3's decision

New `_apply_stage3_decisions` in `src/model/evaluate_pipeline.py`: wherever
`stage3_batch_results.csv` has a decision for an admission, it replaces
`stage2_confirmed` (+ the existing C9 Stage-1 fallback) as the pipeline's
final prediction. Admissions Layer 3 hasn't audited yet (no batch run, no
note, or an `annotation_failed` row) keep the prior C9-corrected value
unchanged — this function can only narrow the gap to the design, never
silently drop coverage. The report gained a `stage3` block reporting how
much of the flagged cohort Layer 3 actually covered.

  was specific enough to execute directly.
- Two decisions were deliberately *not* made: which model runs Layer 3's
  robustness arm (blocked on checking whether PhysioNet's DUA permits a
  cloud API at all — recommended default is a larger local model, not
  assumed), and RQ1's headline denominator (recommended: notes-cohort
  subset for both models, full-population Layer 1 as context only) — both
  need explicit confirmation, not a silent implementation choice.

  can only replace a fallback prediction with a real Layer 3 decision where
  one exists, never remove coverage the C9 fix already established.
