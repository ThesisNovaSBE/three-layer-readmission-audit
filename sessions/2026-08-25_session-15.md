### Root-cause finding: Stage 3 had already been diagnosed and fixed three times, only in prose

Session 11 (2026-07-31) built "Stage 3 v1" — phi4-mini narrating Stage 1's
own SHAP values — and explicitly rejected it in the same session as "a
well-trodden pattern with no novel finding," replacing it with a
"Cross-Modal Discordance Analysis" design that fed phi4-mini a raw
`stage2_score - stage1_score` delta and let it freely classify a 9-category
taxonomy. Three later planning artifacts (methodological evaluation
2026-08-16, Project Brief 2026-08-17, Working Paper undated) each
independently re-diagnosed this as backwards (discordance should be computed,
not classified by the LLM) and converged on the same fix: phi4-mini as an
independent auditor making its own uphold/override call. None of those three
rounds of fixes had reached the actual code — `src/stage3/explain.py` still
had zero `decision`/`uphold`/`override` fields as of this morning.

### The literature review's own contribution (§2.6) was correctly identified as weak

Confirmed with the user: the lit review's locked §2.6 contribution (XGBoost →
phi4-mini directly, reading SHAP + note) is essentially identical to the
"Stage 3 v1" design the team already tried and rejected in session 11 — an
LLM narrating one model's own explanation is the existing "explainer" role in
the lit review's own concept matrix (Table 3), not the "auditor" role its gap
statement claims to fill. The distinguishing property of a genuine auditor is
reviewing an *independent second model's* output, which requires Stage 2 to
exist and to be informationally independent from Stage 1.

### Fixed the raw-subtraction discordance measure (P1 from the remediation review)

The most recent design docs (Project Brief, Working Paper) proposed
"same isotonic calibration on both stages fixes the raw score-gap problem."
This is an assertion, not a guarantee — two different model families
(XGBoost vs. FusionLongformer) are not guaranteed to have equal residual
miscalibration even under the same calibration method, and Stage 1 currently
has no calibration applied at all (Brier 0.2135, worse than the base-rate
constant). Replaced raw subtraction with percentile-rank displacement within
the flagged+noted cohort — invariant to unequal calibration by construction
(added a test proving this: `test_discordance_invariant_to_monotonic_rescaling`).

### Feature-independence claim resolved without retraining

Stage 1 uses ~40 features (incl. labs/vitals); Stage 2's `STRUCT_FEATURE_COLS`
is a different set of 8. The Working Paper's claim that "both models see the
same structured information" is false against the actual code. Considered
cutting Stage 1 to 8 features to make the claim true — rejected (matches the
remediation review's P5: unjustified retraining cost for no clear benefit).
Resolution: keep both feature sets as they are, drop the "clean attribution
to the note alone" claim, and rely on percentile-rank discordance, which
doesn't need identical feature spaces to be meaningful — it only needs each
score to be a valid within-cohort risk ordering.

### Stage 1 operating point: capacity-constrained, not recall-floor

User flagged (independently, before I'd finished listing it) that Stage 1
flagging 66.94% of admissions at `recall_floor=0.85` is not a deployable
triage — matches remediation review P7a. Added
`select_threshold_for_capacity` / `metrics_at_capacity_points` to
`src/model/metrics.py` and switched Stage 1's primary threshold-selection
policy to flag the top `capacity_k` (default 15%) of admissions by risk
score. Recall-floor is retained and reported as a secondary table for
comparability with prior literature (`stage1.threshold_strategy` config
switch).

### Stage 2 sequence length: 2048 → 4096

Session 9 set `max_seq_length=2048` based on an estimate that the average
MIMIC discharge note was ~1,900 tokens. Session 14 (2026-08-10) measured this
properly while investigating radiology-note concatenation and found 74% of
discharge notes exceed 2048 tokens, median ~2,649 — the number that justified
2048 was already known to be wrong and never got carried back to
`config.yaml`. Clinical-Longformer natively supports 4096 (its whole design
point per Li et al. 2022). Bumped it; this is a config-only change, applies
on the next Stage 2 training run.

## Key decisions made

- Stage 3 (phi4-mini) makes its own independent `uphold`/`override` decision;
  it does not narrate or classify Stage 2's decision.
- Discordance mode is computed quantitatively (percentile-rank displacement,
  `src/stage3/explain.py:compute_discordance`), never by the LLM.
- No claim that Stage 1/Stage 2 share a feature space or that their score gap
  is cleanly attributable to the note alone — they use different information
  by design, and that's the whole point of comparing them.
- Stage 1's primary operating point is capacity-constrained (top-K% by risk),
  not a recall floor. Recall-floor kept as a secondary/comparability table.
- Stage 2's context window is 4096 tokens (was 2048).
- `stage3.temperature` pinned at 0 for all evaluation runs.
- Deliberately did NOT touch `src/stage2/predict.py`'s hard-gating
  (`stage2_confirmed` as a threshold decision) or build a batch Stage 3
  runner this session — both require a coordinated decision about the
  API/frontend contract and are explicitly deferred to the next "exact stage
  behaviour" discussion (see `docs/ARCHITECTURE.md` §4).
