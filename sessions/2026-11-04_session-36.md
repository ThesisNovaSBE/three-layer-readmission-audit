## Script execution trace (same session, after the above)

User asked to trace every script's execution path as if running it
(imports, CLI arguments, invocation syntax) without actually running
the real project scripts, to catch anything that would only surface
at run time before "someone or an AI" hits it.

Confirmed one real bug via a safe, isolated reproduction rather than
running the real script: built a disposable mirror
(`src/__init__.py` + `scripts/testscript.py`) in a scratch directory
to test Python's import-path behavior in isolation. `python
scripts/testscript.py` (direct path) failed with `ModuleNotFoundError:
No module named 'src'`; `python -m scripts.testscript` (module form)
succeeded. This confirmed `scripts/analyze_discordance_subgroups.py`'s
own documented usage line, `python
scripts/analyze_discordance_subgroups.py`, was broken, since that
script does `from src.model.bootstrap import bootstrap_ci` with no
`sys.path` manipulation of its own. Fixed the docstring to `python -m
scripts.analyze_discordance_subgroups`, matching the other three
analysis scripts' convention.

Then grepped every `Usage::` / inline invocation example across
`scripts/*.py` and `src/**/*.py`: all other entries already use
module form (`python -m ...`) correctly. The two root-level direct
invocations (`python setup_stage2.py --mode full` in `train_stage2.sh`,
and `setup_stage2.py`/`setup_demo.py`'s own docstrings) are safe
because those scripts live at repo root next to `src/`, which puts
`src` on `sys.path[0]` automatically — the bug class only applies to
scripts one level down in `scripts/`. `scripts/validate_stage3_sample.py`
has no `src` import at all, so it is unaffected either way.
README.md's Utility Scripts table and `MODEL_CARD.md`'s references to
`analyze_discordance_subgroups.py` only ever cite the bare file path
as a label, not as a command, so neither needed a matching fix.

No other invocation-syntax or CLI-argument mismatches found across
`slurm_stage1_tune.sh`, `slurm_stage2_finish.sh`, `slurm_stage3_batch.sh`,
`train_stage2.sh`, or `diagnose_cluster.sh`.
